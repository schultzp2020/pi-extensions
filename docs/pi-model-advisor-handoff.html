Nonnegotiable constraints

Bounded decisions

One configured native classifier answers three choice questions and one bool question. Validate exact labels, finite bounded probabilities, and distribution totals; capability uses ordered-choice percentiles. No generated rationale or model identifier.

Pi owns eligibility

Nonempty scoped models, otherwise authenticated available chat models; physical entries only. Exact capability-group membership and caller requirements remain hard. Task profiles define routine levels; stronger compatible proposals require fresh exact approval. Classifier inventory stays separate.

User owns quality

Exact model configuration supplies capability and priority. Price is only a late tie-breaker.

Orchestrator-neutral

No Paseo dependency, no parent-model switch, and no agent creation.

Fail closed

No fallback. Keep native transport retries; add no custom retry or corrective inference. Inspect native stopReason, preserve failure-path usage, propagate cancellation, and enforce an overall deadline.

Native thinking

Use getSupportedThinkingLevels() and clampThinkingLevel(), with next-higher-then-lower support resolution. Caller minimumThinking/maximumThinking and configured bounds remain hard.

Global configuration

Resolve via getAgentDir(), respecting PI_CODING_AGENT_DIR. Initialize and reload through /reload only; no project overlay, file watcher, or hidden stale snapshot after invalid reload.

One tool

recommend_subagent_model works directly and through native codemode. TypeBox outputSchema matches structuredContent; return nested usage. Read-only/nondestructive, open-world when classification is remote.

Optional pi-subagents integration

Same package, isolated export: @schultzp2020/pi-model-advisor/pi-subagents exposes verifySubagentRecommendation(). Caller injects the official resolveSubagentLaunchContract(), intended launch inputs, and current host snapshots. Rejection, missing host facts, or changed model/thinking returns verification failure; never substitute, launch, or claim approval.

Recommend → read-only verify → approve exact selection when caller policy requires → existing launcher. Stronger task-profile exceptions always require fresh approval and return approval_required. Verification reserves nothing; launch rechecks. Native child effort uses model: "provider/id:thinking". Resolve workflow selections before dispatch; no external CLI translation.

Keep object-style classifier/model identities and capability-group arrays. Model presence controls eligibility; no enabled/local/per-model capability fields. Luna entries pin minimum=maximum=max. Caller ceilings below max exclude Luna, never lower its effort. Duplicate identities are invalid. Task profiles are config-only names with level arrays or { description?, levels }. Callers select taskKind explicitly; unknown names fail input validation. No built-in taxonomy, task-kind question, inference, or separate kind floor remains. Starter profiles: plan advanced/frontier; implement light; review advanced/frontier; research standard/advanced; pull_request standard/advanced.

Task levels are the routine pool, not a hard ceiling. Caller levels, provider/image/context/thinking requirements, Pi scope, and configured membership remain hard. If routine models cannot meet classifier demand, propose one sufficient compatible model above the task's highest level with approval_required. No such model returns no_eligible_model. Empty task/request arrays block recommendations, including escalation. Stronger proposals never relax bounds or trigger classifier fallback.

Accepted defaults: capability percentile 75; consequence thresholds 0.70/0.90; overall deadline 60 seconds; absolute probability-total tolerance 0.0001. Normalize accepted rounding drift for the percentile.

The exact classifier may be hosted or local, including a compatible Clef model through Pi's native llama.cpp provider. Pi owns server setup, optional authentication, inventory, and transport. There is no local-to-hosted fallback.

Remote classification sends explicit task state through Pi. Pi-retained tool arguments/session transcripts are separate from task-free advisor logs. Worker-locality filtering is not supported.
