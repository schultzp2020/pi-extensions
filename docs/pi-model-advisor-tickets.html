Ticket 01

Establish the package and fail-closed configuration diagnostics

Blocked by: None

What it delivers: A loadable Pi 1.0.4 package with native classifier discovery, strict global configuration, explicit /reload behavior, and diagnostics that explain why recommendation is unavailable.

  • The package builds against Pi 1.0.4 using existing monorepo conventions; Pi Cursor's dependency stays unchanged unless compatibility requires otherwise.
  • Strict TypeBox schemas reject unknown configuration keys, invalid policy ranges, and repeated identities with exact issue paths. Keep object-style identities and capability-group model arrays; membership replaces enabled/local flags. Task keys are config-only and may use arrays or objects with levels and optional descriptions; no fixed task-key catalog.
  • Global-only configuration resolves through getAgentDir(), respecting PI_CODING_AGENT_DIR; project overlays are ignored.
  • One exact classifier identifier, hosted or local, is required and checked against getAvailableOfType("classifier"); Pi owns credentials, endpoints, and transport. Support a compatible local classifier such as Clef through Pi's native llama.cpp provider; no advisor endpoint fields or hosted fallback.
  • Missing, invalid, or unavailable classifier configuration yields configuration_error across public surfaces.
  • Nonempty scoped models take precedence; otherwise use Pi's authenticated available chat models. Exclude virtual entries without expanding scope.
  • Configuration loads at initialization and /reload only. Edits remain unapplied until reload; malformed reloaded configuration disables recommendation rather than restoring an old snapshot.
  • Status, models, and doctor distinguish classifier availability from chat-model eligibility; doctor makes no inference call by default.
  • Tests use mocked Pi registries and injected native responses, with no live calls.

Ticket 02

Deliver the first end-to-end native classifier recommendation

Blocked by: 01: Establish the package and fail-closed configuration diagnostics

What it delivers: The recommend_subagent_model tool and preview command submit explicit task state to one configured native classifier and return a deterministic recommendation from Pi-owned physical chat candidates.

  • State contains explicit task/profile data, selected profile description, role, context, and requirements; parent transcripts are never read. Config-only taskKind must name a configured profile. Unknown names are invalid input; no built-in task taxonomy or inference remains.
  • Call ctx.modelRegistry.classify() with three choice questions and one bool question in one request; provider execution need not be parallel.
  • Ordered capability probabilities implement the configurable 75th percentile and consequence floors; native score expectation is not substituted.
  • Effort and context demand use validated native choice labels, with explicit label order and rubrics.
  • Only exact configured physical chat models inside Pi scope and all hard caller bounds may be selected. Request levels replace candidate IDs. Task profiles define routine levels; a sufficient compatible level above the profile ceiling returns approval_required pending fresh exact user approval, never automatic substitution.
  • Pi TypeBox input/output schemas and matching structuredContent expose exact selection, native typed answers, mechanical policy details, and reported nested usage.
  • One ordinary tool works directly and through native codemode; annotations are read-only, nondestructive, and open-world when classification is remote.
  • No code path switches parent model/thinking, launches agents, generates rationale, or provides fallback.
  • Core behavior is injectable for offline tests; full failure-path coverage follows in Ticket 04.

Ticket 03

Apply hard constraints, deterministic ranking, and thinking clamps

Blocked by: 02: Deliver the first end-to-end native classifier recommendation

What it delivers: Recommendations honor caller narrowing, deterministic ranking, and native supported thinking levels while preserving global, per-model, and caller minimum/maximum bounds.

  • Image, context, provider, request levels, and thinking bounds are hard and never expand Pi scope. Task profiles define the normal pool; stronger sufficient compatible models above its highest level require fresh exact approval. Empty task/request lists block both pools.
  • Ranking applies lowest sufficient capability, user priority, semantic context preference, output/input/cache-read price, and exact identity in that order.
  • Use getSupportedThinkingLevels() and clampThinkingLevel(): next supported higher level, then lower, not nearest-level/higher-on-tie.
  • Resolve thinking inside the intersection of global, per-model, and caller bounds. Recheck native results against hard bounds; a native upward adjustment never overrides a ceiling.
  • Invalid configured supported ranges produce configuration_error; inverted caller bounds are rejected as invalid input.
  • A model with no supported level inside caller/configured bounds is ineligible. No surviving candidate returns no_eligible_model with mechanical rejection details.
  • Boundary tests cover custom names/descriptions, unknown-name errors, routine versus hard-level pools, stronger approval_required proposals, no implicit approval, omitted/empty rules, sparse supported thinking levels, both caller bounds, non-reasoning models, and distinct exact provider identities. Include minimum=maximum=max, as required by the user's Luna configuration: lower caller ceilings exclude the model rather than reducing thinking, and max effort never raises capability class.

Ticket 04

Return typed native classifier failures without fallback

Blocked by: 02: Deliver the first end-to-end native classifier recommendation

What it delivers: Native classifier errors, invalid answers, deadlines, and cancellation return typed results, retaining Pi transport retries and billed usage without corrective retries or fallback inference.

  • Inspect native stopReason and errorMessage; do not rely on classify() throwing for reported provider errors.
  • Require exactly the expected question/type identities and labels. Reject unknown keys, missing/duplicate distribution entries, nonfinite or out-of-range values, and probability totals outside the documented tolerance.
  • Keep Pi's native transport retries/timeouts; add no custom retry loop, semantic correction call, secondary classifier, chat emulation, or automatic alternate selection.
  • Propagate tool/ctx abort signals and enforce an overall deadline covering native attempts. Cancellation yields aborted; transport, deadline, and invalid answers yield classifier_failed with distinct categories.
  • Preserve native reported usage on malformed/error responses and carry it through structured tool results for Pi accounting.
  • Offline tests prove every failure discriminator, cancellation/deadline behavior, and absence of fallback or extra semantic inference calls.

Ticket 05

Add optional caller-owned pi-subagents preflight verification

Blocked by: 03: Apply hard constraints, deterministic ranking, and thinking clamps

What it delivers: One isolated same-package export verifies a recommendation against the official pi-subagents launch preflight supplied by the caller, without introducing a launcher or default runtime dependency.

  • Expose verifySubagentRecommendation() at @schultzp2020/pi-model-advisor/pi-subagents, outside default extension/core imports; do not create a separate package.
  • Receive recommendation, intended launch inputs, current host snapshots, and the caller-supplied resolveSubagentLaunchContract() function from the public pi-subagents/preflight export.
  • Missing required host facts (host_required), rejected preflight, or changed provider/model/thinking returns structured verification_failed; exact unchanged selection returns verified.
  • Use no internal-module imports, settings writes, model substitution, new classifier calls, approval claims, or child launches.
  • Verification is neither approval nor reservation: document recommend → verify → approve exact selection → existing launcher, with authoritative launch recheck.
  • Support native Pi children only. Dispatch uses model: "provider/id:thinking"; resolve/approve workflow selections before dispatch and pass exact values into child steps.
  • pi-subagents owns defaults, scopes, thinking ceilings, and launch approval. Routine implementation uses max-thinking light Luna; stronger proposals require fresh exact user approval. Read-only preflight must accept a proposed selection without treating verified as approval or clearing approval_required. Role defaults alone do not enforce restrictions.
  • Compatibility tests use published pi-subagents 0.76.1 as a development dependency, alongside mocked rejection, missing-host, and adjustment cases; generic imports must work without that runtime package.

Ticket 06

Complete command UX, privacy-safe observability, and core reuse

Blocked by: 03: Apply hard constraints, deterministic ranking, and thinking clamps; 04: Return typed native classifier failures without fallback

What it delivers: Users and Pi extensions inspect, preview, diagnose, and reuse one advisor contract with native structured results, accurate usage, explicit reload behavior, and documented privacy boundaries.

  • Bare status, recommend, models, config, and doctor commands share validation and clearly identify the /reload-only configuration boundary.
  • The injected reusable recommendation core requires neither ExtensionContext nor pi-subagents.
  • Recommended, approval_required, configuration_error, no_eligible_model, classifier_failed, and aborted are exhaustive; native choice/bool answers retain their types.
  • Tool outputSchema matches structuredContent on every result path, and reported nested usage reaches Pi accounting; details alone are insufficient.
  • Advisor metadata omits task text by default and records classifier identity, bounded answers, candidates, selection, and failure category; full task logging requires explicit opt-in.
  • Privacy documentation explains classifier outbound traffic and distinguishes advisor logs from Pi's retained tool arguments/session transcripts.
  • Commands and results use mechanically derived text, not generated rationale; no separate codemode adapter or MCP export server is added.
